# 多个助手共用一个本地项目库

每个项目绑定到一个独立 SQLite 文件。工具由各客户端启动，数据库文件可以在工作目录以外。项目库保存项目决定与任务卡。记录注明说话人、写入端及逐项版本。现有 Harness 自动摘要缓存和个人长期记忆库仍是独立存储。

## 开始使用

在已安装本仓库的虚拟环境中，从仓库根目录执行：

```sh
.venv/bin/python scripts/bind_project.py --workspace /absolute/path/workspace-A \
  --db ~/.memorygene/projects/example/decisions.sqlite --name mg_example --grok --turn-hooks
```

把 workspace-A 换为第二个工作目录，再运行一次，即可绑定同一项目。文件路径和解释器路径均为本机路径。复制到另一台机器需要重新绑定。请选择自己管理的项目目录，并保留客户端对项目配置的正常信任提示。

- **DSH**：启用逐轮采集后，在绑定的目录运行 `.memorygene/start-dsh-turns`；仅使用共享工具时运行 `.memorygene/start-dsh`。脚本启动 TUI 并加载项目工具。已有桌面版用户可在绑定时指定 `--dsh-desktop`，下次加载该桌面 profile 后可用。
- **GPT / Codex**：在绑定的目录打开 Codex，批准自己信任的项目配置。若该版本只发现用户级 MCP，可显式使用 `codex mcp add NAME -- /absolute/path/.venv/bin/python -m memorygene.project serve --db /absolute/path/decisions.sqlite --client gpt`。此配置用于 Codex 客户端。
- **Claude Code / Desktop**：在绑定目录启动 Claude Code，通过正常提示启用该项目的 MCP。macOS Claude Desktop 可在绑定时加 `--claude-desktop`，保存其他工作后重新打开客户端。在桌面聊天中明确使用对应的项目工具。
- **Kimi Code**：打开绑定的项目目录，启动 Kimi Code，按客户端提示登录并确认项目。安装器写入项目级 `.kimi-code/mcp.json`。此配置用于 Kimi Code 客户端。
- **Grok Build**：绑定时加 `--grok`。在自己的项目中允许 Grok 使用项目配置，然后运行 `grok mcp doctor 项目工具名 --json` 检查连接。项目配置显式标记写入端为 Grok，版本历史可区分 Grok 与 Claude。

两个桌面选项及 Codex 用户级注册会在该客户端的其他会话中提供这个命名项目的工具。工作目录提示负责指导何时使用；文件持有者和已绑定客户端能读取该项目。这不构成按窗口鉴权。需要严格按工作区绑定时，仅使用项目级配置。请勿提交生成的含本机路径的配置。

## 在两个客户端之间交接

1. 在第一个助手中说：“当前任务是 release，请记住生产环境和测试环境的日志都保留 7 天。”
2. 在另一个助手中说：“接手 release。仅生产环境的日志改为保留 30 天，测试环境仍为 7 天。”
3. 回到原会话问：“两个环境各保留几天？请引用这次修改的原话。”

同一个任务应使用同一任务名和条目名。记录建议先按任务读取，找到旧条目后使用已有名称。现阶段键名是小写英文、数字、点、下划线或连字符；如果模型选了不同的键，会形成两条独立记录。工具返回原始引用和写入端，跨端引用没有经过另一端聊天记录的独立核验。

## 决定与版本

- `project_read`：读取某个任务的当前决定，也可精确到一个条目。列表最多 20 条，超过会标明省略。
- `project_update`：提交单项修改，同时给出读到的版本与用户原话。第一次写入用 0。并发修改同一旧版本，只有一个写入成功，另一个收到冲突，需要重新读取并判断。
- `project_history`：读某条决定的最近 20 个版本，包含原话、值和记录方。指令约定在恢复任务和依赖某项决定的操作前读取。客户端是否实际调用要以工具记录为准。

## 跨助手任务卡

- `task_record` 将目标、要求、偏好和步骤分项保存。步骤可标为待做、进行中、已完成或取消。用户决定和助手报告使用各自的说话人字段。版本不一致时重读原条目。新建条目（`expected_version` 为 `0`）时，若同任务下已存在高相似键名，会在返回结果的 `similar_items` 中提示，便于合并或复用已有键名。
- `task_resume` 根据任务名或描述查询本地词索引（任务内按词频稀有度加权）。未指定任务并且可能匹配多项时返回候选；带 `query` 恢复时会在 `relevant` 中返回最相关的条目，逐轮前景数据包也会优先置顶这些条目。按页读取完整值和证据；短摘要中的省略内容仍可取回。`task_check` 对照上下文携带的条目版本，返回遗漏、已变更或需要复查的项。交接前读完所有页面。可传入上下文记得的原值；即使版本相同，值不同也会返回当前完整记录。
- `task_search` 在当前任务内检索条目。`task_related` 沿已记录的依赖追溯变化。更改要求后，下游步骤保留原有状态并显示需要复查。助手需要核实实际成果。
- 要真正删除某条记录，明确指定任务与条目，使用 `task_remove` 和读到的版本。它会清除此条目的内容、原话和历史，以及本任务临时缓冲，仅保留防止旧写入复活的版本号。已取消和已完成的目标退出自动匹配，仍可按任务名查阅。
- 两位助手对同一条要求有不同意见时，可用 `task_propose` 保留备选说法。选定方案后，使用用户的确认原话和当前版本写入，旧版本保留。
- 目标的工作模式可选 `auto`、`coding`、`study`、`general`。自动模式使用目标和当前描述；也可显式更正模式。编程模式会引导先对齐假设与约束并验证改动，学习模式区分材料原文和补充说明。项目通用偏好放在 `defaults` 任务，具体任务中的同名偏好覆盖默认值；若偏好键名带有 `coding.`、`study.` 或 `general.` 前缀，恢复任务时会自动过滤掉其他模式的偏好，并优先加载当前任务且匹配当前模式的偏好。
- 项目工具能够更新外部项目库。各客户端管理自己的账户记忆和指令权限。

## 逐轮采集与预拍

使用绑定参数 `--turn-hooks` 为选定工作目录配置本地钩子。DSH 使用逐轮启动器；桌面端可同时传入 `--dsh-desktop`，重新打开后，从绑定目录或其子目录创建的会话才参与逐轮采集。Codex 还需审核提交消息和回复结束两个钩子；Grok Build 在受信目录中运行钩子，助手通过项目工具读取任务卡。无钩子时仍可用工具维护共享任务卡。

识别到任务后，本地缓冲最多保留前两条短消息。明确改口可开启两分钟的临时片段，保留改口原句及同一任务中的后续限定。疑问、犹豫和无法定位的任务会限制采集。助手可用 `task_clip` 查看或放弃片段；用匹配原话和片段编号成功写入后，会在同一事务内删除临时片段和对应缓冲。持久任务卡仍保留最终选取的证据。长消息不会作为完整预拍证据保存。

原话缓冲五分钟过期；同会话接续用的任务标识最多保留七天。服务运行时定期清理，关闭期间过期的内容在再次使用时清理。宿主的聊天历史由宿主管理。限定格式的进度消息，例如“待办：核对总额”和“已完成：核对总额”，可由钩子直接保存；自由表达的进度由助手结合任务工具整理。每轮钩子使用本地数据库，不单独调用模型。
