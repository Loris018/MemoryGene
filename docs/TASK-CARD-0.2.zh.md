# MemoryGene 任务卡 0.2：使用与验证边界

在启用插件的 DeepSeek Harness 对话里，正常工作即可积累进度。后台按阈值整理，不需要每次说“记住”。

## 可以直接这样说

| 想做什么 | 对助手说 |
| --- | --- |
| 查看进度 | “显示任务卡，列出当前要求、待办和需要复查的成果。” |
| 修改要求 | “把纸张要求改为 A1，并更新任务卡。” |
| 标记状态 | “这项待办已经完成／取消，请更新任务卡。” |
| 确认复查 | “我已经按新要求重新检查了 PDF，请记录我的确认。” |
| 删除一条 | “从任务卡删除这条记录。” |
| 暂停／恢复 | “暂停自动记录。”／“恢复自动记录。” |
| 清空本次缓存 | “清空这次任务卡，并暂停自动记录。” |
| 准备交接 | “导出这项任务的接续包。” |

操作只作用于当前会话的任务卡。更正和状态变化需要引用本轮用户原话；更新前核对卡片版本，防止较旧操作覆盖新要求。已明确更正的记录会保留，不会被后台摘要悄悄改回。

## 修改影响如何识别

摘要记录要求与成果之间明确的依赖。例如：纸张尺寸 → 海报 PDF → 打印件；数据集 → 文案。尺寸变化后，PDF 和依赖 PDF 的打印件显示“需要复查”，文案不因此自动失效。

这些依赖由模型提取，是可能出错的记录。依赖未知、缺少上游记录或形成循环时，不显示已验证。只比较记录中的要求文本，因此换一种说法也可能触发复查。没有检查真实文件内容就不能说文件已经正确。

## 接续检查的实际范围

当前检查原话引用、是否保留目标和下一步、旧要求是否被遗漏、是否有尚未整理的新消息和可能受影响的成果。这是结构检查，不是独立模型模拟接续，也不是任务完成证明。缺少信息时显示待复查，普通对话继续，不等待额外的前台模型调用。

## 清空和暂停

清空会删除插件缓存中的任务内容并暂停采集，同时阻止旧后台结果重新写入。它不删除 Harness 原对话、已经进入上下文的历史消息或 MemoryGene 的个人长期事实。暂停期间不持久保存新对话；本轮用户要求恢复时，控制工具仍能读取这条要求来执行恢复。

## 跨助手接力的当前范围

可以导出带来源、检查结果和变更影响的 JSON 接续包。校验值用于发现意外修改，不证明身份或真实性。接收方需重新核对来源、当前要求和授权范围。没有实现自动导入或自动续跑，不能宣称已经无缝跨助手迁移。
